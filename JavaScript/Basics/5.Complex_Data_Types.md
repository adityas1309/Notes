## Key Data Type: `null`

### Understanding `null` vs `undefined`

Both `null` and `undefined` represent **emptiness**, but they serve different purposes:

- **`undefined`**:
  - Indicates that a **variable was declared but not assigned a value**.
  - It’s the default value JavaScript assigns to variables that are declared but uninitialized.

- **`null`**:
  - Represents an **explicitly empty value**.
  - Used when a developer wants to signify that a variable has **no value on purpose**.

> 🧠 Think of `undefined` as "not assigned yet" and `null` as "assigned to nothing".

### Real-World Analogy

Imagine a toilet paper holder:

- **Holder with paper:** Value exists (non-zero).
- **Holder without paper:** Represents `null` (holder exists, but the paper is empty).
- **No holder at all:** Represents `undefined` (not set up yet, but could be in the future).

This analogy clearly separates the meaning between these two values in a physical context.

### Coding Examples

```javascript
let a;             // a is undefined
let b = null;      // b is explicitly null
let c = 10;        // regular number
```

```javascript
console.log(a);    // undefined
console.log(b);    // null
console.log(c);    // 10
```

> ✅ `null` and `undefined` are both **JavaScript keywords** and should be written in **lowercase**.

## Printing and Testing Values

Using `console.log()`, we can test how each data type behaves when printed.

```javascript
var marks = 100;
var name = "Aditya";
var age;
var company = null;
var salary = undefined;
var isStudent = false;

console.log("marks =", marks);           // 100
console.log("name =", name);             // Aditya
console.log("age =", age);               // undefined
console.log("company =", company);       // null
console.log("salary =", salary);         // undefined
console.log("isStudent =", isStudent);   // false
```

**Key Takeaways:**
- Declaring without assigning → `undefined`
- Explicitly setting to `null` → emptiness
- Both values **print as-is** in the console.

**Summary:**  
Understanding the differences between `null` and `undefined` helps you express the correct data state in JavaScript programs.

## Representing Complex Entities with Objects

When working with real-world data like users, products, or configurations, a single value (string, number, etc.) is not sufficient.  
That's where **JavaScript objects** come in.

### Syntax and Structure

- An object is created using **curly braces `{}`**.
- It stores **key-value pairs**, where:
  - **Key** is a string (written without quotes).
  - **Value** can be any valid JavaScript type.

```javascript
var user = {
  name: "Aditya",
  company: "Google",
  age: 20
};
```

### Example Object

```javascript
console.log("Details of the user is", user);
```

**Console Output:**
```
Details of the user is { name: 'Aditya', company: 'Google', age: 20 }
```

- Keys must be **unique** within an object.
- Values can include:
  - Strings (`"Google"`)
  - Numbers (`20`)
  - Booleans (`true` / `false`)
  - `null` or `undefined`
  - Even other **objects** (nested structure)

> 🧠 An object allows combining **multiple primitive types** into a single meaningful structure.
